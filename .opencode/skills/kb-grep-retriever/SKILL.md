# 目标

在当前项目的 Markdown 文档中，通过「关键词提取 + grep 搜索 + 多轮迭代」来检索与用户问题相关的上下文，
在不依赖向量索引的情况下实现 RAG 风格的知识检索，并基于真实命中文档作答，避免幻觉。

默认假设仓库中存在大量 `*.md` 文档（文档站 / 知识库），且当前工作目录为仓库根目录。

# 适用场景

- 用户询问的问题有较大概率可以在当前 Markdown 文档站中找到答案，例如：
  - 使用说明、设计文档、接口文档、产品需求、操作手册、FAQ 等。
- 问题包含比较明确的名词、术语、模块名、文件名、接口名等。
- 不需要调用外部 API 或远程检索，只依赖当前仓库内容即可回答。

如果用户问题明显是开放式头脑风暴、创作类任务、与当前仓库内容无关，则不必调用本 Skill。

# 总体流程

1. 解析用户问题，提取候选检索关键词（词组）。
2. 生成多组检索关键词组合，并排序（优先级从高到低）。
3. 按顺序对关键词组合执行 grep 搜索，分析返回的上下文。
4. 如果当前检索结果无法有效回答问题，则调整关键词组合继续检索。
5. 最多尝试 5 轮检索；在合理命中后整理上下文并作答。
6. 如果 5 轮后仍无法获得有效信息，明确告知用户文档中未找到答案，而非编造。

# 1. 从问题中提取检索关键词

- 抽取 3–8 个具有区分度的名词 / 名词短语，覆盖：
  - 领域关键词（例如：权限、计费、分页、缓存、一致性）。
  - 功能模块 / 组件名（例如：数据集、数据源、pipeline、worker、调度器）。
  - 专有名词（接口名、类名、文件名、配置项等）。
- 处理多语言情况：
  - 如果问题中同时出现中英术语，优先保留原始形式，例如：
    - `EasyDataset`、`DatasetProvider`、`/api/v1/datasets`。
  - 不要把技术名词拆开或翻译成别的词。
- 去掉无意义或极高频词：
  - 如：如何、怎么、是否、可以、以及、一个、我们、他们、系统、功能、解决、支持、实现 等。
- 尝试构成多种粒度的关键词：
  - 粗粒度：`数据集 权限`、`增量 同步`。
  - 精细粒度：`dataset permission`、`incremental sync`、`dataset_visibility`。
- 如果问题中包含明显的章节标题 / 文档标题线索，也作为关键词：
  - 例如 “参考『快速开始』文档中的做法”，则加入 `快速开始`、`quick start`。

# 2. 生成关键词组合（检索计划）

在内部构造一组有序的「关键词组合」用于多轮检索，每组为 1–3 个关键词：

- 第 1 轮优先使用最核心 + 最具体的关键词组合：
  - 如：`["数据集", "权限"]`、`["DatasetProvider"]`。
- 第 2–3 轮用稍微放宽的组合：
  - 只保留 1 个核心词：`["数据集"]`、`["dataset", "permission"]`。
  - 或替换为同义 / 相关词：`["授权"]`、`["访问控制"]`。
- 第 4–5 轮再尝试：
  - 组合不同词序或单复数的变体：`dataset` / `datasets`，`config` / `configuration`。
  - 尝试中英文互译：`权限` <-> `permission`，`快速开始` <-> `quick start`。
- 记录已经用过的关键词组合，避免重复同一组合。

示例内部结构（伪代码，说明逻辑即可，无需真的编码）：

```text
candidates_round_1 = [
  ["DatasetProvider"],
  ["数据集", "权限"],
]

candidates_round_2 = [
  ["数据集"],
  ["dataset", "permission"],
]

candidates_round_3 = [
  ["授权"],
  ["访问控制"],
]
```

最多只需要准备到 5 轮；如果自然提前命中足够信息，可以提前结束。

# 3. 使用 grep 执行检索

优先使用提供的 `Grep` 工具；若只能用 shell，则使用 `grep` 命令。核心目标是：在 Markdown 文档中找到包含关键词的上下文片段。

## 3.1 通用命令模板

- 递归检索 Markdown 文档：
  - 工具形式（推荐）：
    - `pattern` 使用正则；`include` 仅匹配 `*.md`。
  - shell 形式（如环境允许使用命令行）：
    ```bash
    grep -RIn --include="*.md" -C3 "关键词或正则" .
    ```
    - `-R` 递归当前目录。
    - `-I` 忽略二进制文件（可选）。
    - `-n` 显示行号。
    - `-C3` 显示上下文 3 行。

## 3.2 单关键词检索

- 对于仅有 1 个关键词的组合，例如 `["DatasetProvider"]`：
  - pattern 可以直接为该词，注意必要时转义特殊字符。

## 3.3 多关键词检索

- 多个关键词时，优先在「单个文件内同时包含所有关键词」的区域搜索：
  - 可以使用多次 grep 逐步过滤：
    ```bash
    grep -RIn --include="*.md" "关键词1" . | grep "关键词2"
    ```
- 如果环境中 `Grep` 工具有更高级的过滤参数，可以用「文件包含关键词1且上下文再匹配关键词2」的策略。
- 若多关键词结果太少，可以退化为单关键词检索。

## 3.4 控制上下文大小

- 每次 grep 返回的结果用「文件路径 + 行号 + 上下文」的形式读取。
- 对同一文件内多行命中：
  - 可以将相邻行合并为一个更大的上下文块。
  - 如果某一文件命中很多次，但相距较远，可以只选最相关的 3–5 段。
- 避免一次性载入整文件内容；优先使用 `-C` 的上下文行或拆分后的片段。

# 4. 多轮检索与停止条件

实现以下控制逻辑（思维层面执行，不需要真实编程）：

1. `max_rounds = 5`。
2. 对每一轮关键词组合：
   - 构造一句「当前检索假设」，例如：
     - 「尝试用关键词 ['数据集', '权限'] 在 Markdown 文档中搜寻与访问控制相关的描述。」
   - 执行 grep 检索并收集上下文片段列表（包含文件路径、粗略标题、片段文本）。
   - 评估这些片段是否足以回答用户的问题：
     - 是否直接给出了定义、配置方法、使用步骤、参数解释、示例等？
     - 是否与用户问题中的关键约束 / 场景高度相关？
3. 如果某一轮结果明显高度相关：
   - 立即停止后续检索，转入「整理与作答」步骤。
4. 如果结果很少、泛泛而谈或与问题明显不符：
   - 记录该轮尝试（所用关键词组合）。
   - 根据现有结果对下一轮关键词做轻微调整（例如换同义词、减小范围）。
   - 继续下一轮，直到：
     - 已尝试 5 轮，或。
     - 所有关键词组合都已用尽。
5. 如果 5 轮后仍然没有足够信息：
   - 明确告诉用户「在当前文档中没有找到关于 X 的清晰说明」。
   - 不要猜测或编造文档中不存在的行为 / 配置项。

# 5. 上下文整理与回答策略

在已经获得一批看起来相关的上下文后，按以下步骤回答：

- 文档归类：
  - 按文件路径、标题（如 Markdown 的 `#` / `##` 标题）对片段做粗略聚类。
  - 同一主题下的多段内容可以合并理解。
- 信息提炼：
  - 抽取文档中的关键结论、限制条件、步骤、参数说明。
  - 如有示例代码 / 配置，说明其用途和前提，而非完全原样堆砌。
- 引用与可追溯性：
  - 在回答中尽量指明信息来源（文件名或大致章节名），例如：
    - 「根据 `docs/dataset/permission.md` 中的说明，……」。
    - 「在『快速开始』文档的『权限控制』章节中提到，……」。
  - 不必输出完整路径和行号，但可在需要时简要提及。
- 不确定性说明：
  - 如果文档对某一细节没有明确说明，或者不同文档存在冲突：
    - 明确指出这一点。
    - 给出「在现有文档中的最佳解释」而不要强行统一。
- 回答风格：
  - 以「基于文档内容的总结」为主，而非凭常识自由发挥。
  - 当文档提供了具体步骤/配置，优先按照原逻辑整理；如需改写或补充，可以在语气中说明是推断/建议。

# 6. 特殊情况处理

- 完全没有命中：
  - 所有 5 轮检索都没有任何结果：
    - 明确回复：「在当前 Markdown 文档中没有找到与问题明显相关的内容」。
    - 可以适度基于常识给出建议，但需要清楚标记为「基于经验推断，不是文档原文」。
- 命中很多但都较浅：
  - 文档只给出模糊介绍而无细节：
    - 明确说明文档的覆盖边界，例如「当前文档只简单介绍了 X 的概念，没有给出具体操作步骤」。
    - 可以给出合理的下一步行动建议（如建议补充文档、查看代码、询问维护者）。
- 多语言 / 命名风格不一致：
  - 若同一概念在中文文档与英文文档中用不同词：
    - 通过上下文联系（例如相同文件中的中英文小标题）推断并在回答中指出等价关系。
    - 例如：「文档中 'dataset visibility' 即『数据集可见性』」。

# 7. 使用本 Skill 的提示（给调用者）

- 当你需要「在当前文档站中找答案」时，调用本 Skill。
- 在调用前尽量让用户问题中包含：
  - 具体的模块 / 功能名称。
  - 尽可能准确的术语或接口名。
  - 相关的上下文场景（例如「在多租户环境下」）。
- Skill 会自动：
  - 从问题中提取关键词。
  - 通过 grep 在 Markdown 文件中检索。
  - 多轮迭代（最多 5 次）优化关键词。
  - 整理命中的上下文并给出基于文档的回答。
